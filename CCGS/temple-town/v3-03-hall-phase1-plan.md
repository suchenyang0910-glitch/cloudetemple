## 一人公司检查

1. **AI 是主要生产力**：[用户决定] 第 1 期只做云寺、一位代表访客和上香流程；建筑用低面数结构，材质从已审核的 2D 原画提取，100 个坐垫只用一份几何和一张贴图批量绘制，不为每个位置单独作图。[假设] 最小版本工作量为 11–17 人日；若现有 15 张人物帧可以直接复用，则取下限，否则只补缺少的背面/斜侧帧，不外包整套 3D 人物。
2. **情感细分、自带传播**：[假设] 可分享时刻仍是完成一次上香后的现有分享卡，不为 3D 新造积分、等级或假热闹。验证指标：进入 3D 殿后成功开始上香率 ≥60%、开始后的完成率 ≥50%、完成后的分享率 ≥5%；连续两周低于任一门槛，则保留 2D 为默认、停止扩到其余活动与寺院，先查加载和操作门槛。
3. **轻量化、单人可运营**：[假设] 静态资源走现有 CDN，异常沿用现有日志和每日运维摘要；每天只需看一次加载失败/5xx（≤10 分钟），每周看一次三项验证指标（≤20 分钟），日均人工运营目标不超过 30 分钟。首期不增加实物、仓储、物流、人工逐条配置或人工客服；增量月成本目标为现有服务器/CDN额度内，若流量突增则先降画质档、延迟加载殿内资源，而不是扩充人工。

[用户决定] 七座寺的佛堂都按“至少 100 个坐垫位”的同一空间模板建设；云寺先做样板，各寺只替换建筑样式、配色和主尊剪影。[假设] 南传区域 `[南传寺名占位]` 的坐垫形式、间距和礼拜习惯须寺院顾问确认，未确认前不照搬北传活动动作。

### 1.2 坐垫阵列与坐标公式

[用户决定] 100 个位置全部面向 `+z`（佛位）。真实多人接入前，画面里只有当前用户；其余 99 个坐垫保持空置，不放假人、不显示假在线人数。

[假设] 坐垫直径 0.72m，列内中心距 1.10m，前后排中心距 1.00m；中轴走道净宽 1.90m，两侧走道净宽约 1.63m。行号 `r=1…13` 从佛前向寺门递增，列号 `c=1…8` 从左向右递增：

```text
z(r) = 14.50 - (r - 1) × 1.00

当 c=1…4：x(c) = 1.99 + (c - 1) × 1.10
当 c=5…8：x(c) = 7.91 + (c - 5) × 1.10

删除四个位：(12,1)、(12,8)、(13,1)、(13,8)
有效坐垫数：8 × 13 - 4 = 100
```

文字俯视图（上方为佛位）：

```text
z=20.50  ┌────────────── 佛台 / 主尊 ──────────────┐
         │             供桌 → 香炉                 │
         │          上香/一键到佛前区              │
z=14.50  │ ● ● ● ●  ║  中轴走道  ║  ● ● ● ● │  r1
         │ ● ● ● ●  ║   1.90m    ║  ● ● ● ● │
         │                 …                       │
z=3.50   │   ● ● ●  ║            ║  ● ● ●       │  r12（外角空）
z=2.50   │   ● ● ●  ║            ║  ● ● ●       │  r13（外角空）
z=0      └────侧走道──── 寺门 / 回门点 ───侧走道───┘
```

[假设] 坐垫阵列、走道与镜头参数作为七寺通用模板；每寺只换殿内结构材质、主尊剪影和供桌细节。100 个坐垫用一个 `THREE.InstancedMesh`、一份几何和一张纹理绘制。

[用户决定]
