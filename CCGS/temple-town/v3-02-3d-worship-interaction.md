## 2. 行走

### 2.1 输入方式

- [已验证事实] 小镇 P0 的 `town-3d/app.js:197–268` 已实现：轻点地面设置目标；按住后左右拖动控制方向并持续向前；桌面可用方向键或 WASD。
- [用户决定] 殿内沿用“轻点地面走过去”和“按住拖动持续走”，不新增虚拟摇杆。
- [假设] 单指位移超过 10px 后进入持续行走；轻点与拖动阈值沿用 P0，待 iPhone、Telegram WebView 与中低端安卓真机校准。
- [用户决定] 活动进行中锁定普通行走，避免误触离开动作位；结束或主动退出后恢复行走。

### 2.2 小镇可走范围与边界

- [已验证事实] P0 的 `town-3d/logic.js` 将小镇可走矩形定义为 `x=-16…16、z=-15…19`，人物碰撞半径默认 `0.34`，寺庙中心半径 `2.2` 内不可进入。
- [已验证事实] P0 距寺门 `1.5` 内显示进入面板，且只存在用户自己的一个访客；证据为 `nearestTemple()`、`canOccupy()` 与 `town-3d/evidence/README.md`。
- [假设] 第 1 期保留矩形外边界，但把建筑阻挡从“中心圆”升级为墙体、台阶、树池和水面的盒体或多边形；碰撞只阻止穿越，不产生反弹或伤害表现。
- [用户决定] “回到寺门”把人物送到当前寺门外的安全落点，镜头同步回到小镇跟随状态；它是文字按钮，不要求用户原路走回。

### 2.3 殿内可走范围与便捷入口

- [假设] 殿内可走区使用一块从门槛到供桌前的中央多边形，扣除佛台、供桌、香炉、柱子、墙体、油灯与活动道具的碰撞盒。
- [用户决定] 人物不能走上佛台、供桌、香炉、矮桌或蒲团，也不能穿过这些物件。
- [假设] 走到活动点约 `0.8–1.2m` 时自动减速并停到预设锚点；半径在第 1 期真机样板中校准。
- [用户决定] 殿内常驻“回到寺门”，把人物送到门内起点；另提供“不走路直接拜”入口，一键走位或淡入到佛前等候点。
- [用户决定] 一键到佛前只跳过走路，不跳过活动动作，也不改变完成记录。

## 3. 镜头

### 3.1 小镇跟随镜头

- [已验证事实] P0 的 `town-3d/app.js:282–292` 使用固定偏移跟随人物，并以插值平滑移动；地图模式切换到固定俯视机位。
- [用户决定] 小镇保持第三人称跟随，不开放自由轨道相机、360°环绕或从建筑内部穿越。
- [假设] 镜头目标点落在人物前方约 `4–6m`，人物位于画面下方三分之一；实际距离按 393×659 构图校准。

### 3.2 进殿过渡

- [假设] 人物抵达寺门并点击 `Vào chùa` 后，先淡出小镇环境声与镜头，再加载殿内必需资源；资源就绪后从门内后上方淡入，过渡目标为 `0.6–1.0s`。
- [用户决定] 减少动效模式取消镜头飞行，只做短淡化；加载失败时保留返回 2D 和回到小镇两个选项。
- [假设] 殿内资源未完成时不让人物进入空场景，旧画面保持可见，并使用不遮挡主尊位置的小型加载提示。

### 3.3 殿内镜头限制

- [用户决定] 默认镜头高于人物头顶、略偏后或侧前方；礼拜、合掌、木鱼、念珠和静坐时，人物始终面向佛位且佛位在画面内。
- [假设] 殿内相机高度约 `1.8–2.4m`，人物距离约 `3.5–5.5m`；横向转动限制在中轴两侧约 `±35°`，俯仰限制在约 `-8°…18°`。
- [用户决定] 活动镜头不能从佛位背后、脚下或低角度仰拍，也不能穿过供桌、柱子或人物。
- [用户决定] 上香和礼拜可缓慢推近；减少动效模式保持静态构图。

- [用户决定] 礼拜蒲团位于中轴，人物在蒲团上礼拜；上香不用蒲团，上香时蒲团隐藏或不进入人物脚下。
- [用户决定] 木鱼矮桌位于跪姿人物前方、朝佛的一侧；木鱼稳放于小垫上，人物手与木槌是同一动作帧，不分离。
- [用户决定] 念珠交互位在人物右后侧的屏幕边缘方向，不在佛与人之间；世界中的念珠位只负责人物站位或跪位，珠串本体可使用前景交互层。
- [用户决定] 静坐位保持中轴或轻微偏侧，人物面向佛位；画面只保留大计时、`Bắt đầu`、设置摘要、`Tùy chọn`与返回。
- [假设] 佛位与供桌前方设一个不可放 UI 的屏幕保护区；香炉、人物脸、手部与活动道具分别有动态保护框。

## 5. 五个活动在 3D 殿内的流程

### 5.1 上香 `Thắp hương`

- [用户决定] 走位：人物从门内或当前点走到右侧油灯与香炉之间的点香位；上香全过程不用蒲团。
- [用户决定] 开始：靠近香炉后出现主按钮 `Thắp ba nén hương`；不点击主尊。
- [用户决定] 动作：走到佛前 → 点香 → 退后一步到拜位 → 手持三炷香拜三下 → 上前插香 → 合掌静立；香头始终朝上并朝向佛位，不出现用口处理香火的动作。
- [已验证事实] 现有 2D 引擎在 `app.js` 已有 8 个上香姿势、6 位访客共 48 帧、60 秒计时与满 20 秒提前结束；证据为 `incensePoses`、`startIncenseStep()`、`advanceIncense()` 与 `v2-03-incense-l2-flow.md`。
- [假设] 镜头在人物后侧约 60–80°，同时完整保留佛位、香炉和人物全身；点香时只小幅靠近手与油灯，拜与插香时回到文化安全构图。
- [用户决定] 结束：人物回到拜位静立；用户可选择继续留在殿内、回到门口或回小镇。

### 5.2 礼拜 `Lạy Phật`

- [用户决定] 走位：人物走到中轴蒲团后方，自动转向佛位，踏上或跪到蒲团中心。
- [用户决定] 开始：靠近蒲团显示礼拜入口，仍沿用 3 / 27 / 54 / 108 与自动慢拜选择。
- [用户决定] 动作：站立合掌举到额前 → 跪下 → 俯身、额头近地 → 起身；不出现双臂举过头。
- [已验证事实] 现有 2D 引擎每位访客有 3 帧礼拜图，共 18 帧；`bowFrame()` 与 `advanceBow()` 已处理慢拜节奏、音效和计数。
- [假设] 镜头固定在侧后方，人物全身、蒲团和佛位都入画；每拜之间镜头不切换，减少眩晕和画面抖动。
- [用户决定] 结束：人物起身后仍面向佛位，再退到蒲团后方等候点。

### 5.3 木鱼 `Gõ mõ`

- [用户决定] 走位：人物走到礼拜蒲团邻近的木鱼位，跪坐并面向佛位；矮桌和木鱼在人物前方。
- [用户决定] 开始：点击木鱼或主按钮开始；木鱼和矮桌是场景道具，木槌画在每位人物手里并随手一起动。
- [用户决定] 动作：落槌 → 手腕小幅抬槌 → 回落；快速连点和自动慢敲都不能让手与槌分离，槌头不能穿入木鱼。
- [已验证事实] 当前 2D 引擎以 `mo-1-v3`、`mo-2-v3`、`mo-3-v3` 三帧驱动六位访客，并用共用矮桌与木鱼道具；证据为 `app.js:112–148` 与 `runWoodMotion()`。
- [假设] 镜头位于人物右后侧，矮桌低于人物视线，佛位与供桌仍完整可见。
- [用户决定] 结束：停止自动模式后人物保持跪坐；退出时起身并回到蒲团后方或门内等候点。

### 5.4 静坐 `Ngồi yên`

- [用户决定] 走位：人物走到静坐位，转向佛位后坐下；人物、蒲团与佛位三点保持同轴或视觉上明确朝向。
- [用户决定] 开始：主界面只留大计时、醒目的 `Bắt đầu`、设置摘要、`Tùy chọn`和返回；时长、呼吸节奏、背景声放入设置面板。
- [用户决定] 动作：坐下 → 双手叠放 → 可选轻微呼吸起伏 → 结束后静止；减少动效时取消身体缩放。
- [已验证事实] 当前 2D 引擎已实现该简化布局、1 / 3 / 5 / 10 分钟、暂停、提前结束、背景声与可选呼吸引导；证据为 `app.js:262–267`、`startBreathing()` 与 `finishSit()`。
- [假设] 镜头从侧后方看向佛位，计时 UI 放在底部安全区，不压人物、蒲团、供桌或佛位。
- [用户决定] 结束：人物保持坐姿，用户点击返回后再起身并回到静坐位旁的等候点。

### 5.5 念珠 `Lần chuỗi`

- [用户决定] 走位：人物走到念珠位后跪坐或坐稳，始终面向佛位；珠串不得位于佛与人之间。
- [用户决定] 开始：点击珠串或在下半屏向下滑动拨一颗；换手只改人物持珠手和触控逻辑，不把珠串移到佛侧。
- [用户决定] 动作：持珠静止 → 拨珠 → 复位，快速输入时保留最新动作；第 108 颗后进入完成状态。
- [已验证事实] 当前 2D 引擎已有六人 × 三帧侧面念珠、珠串拖动、计数节点、读屏节流和 108 颗完成逻辑；证据为 `app.js:270–272`、`beads.js:29–77` 与 18 张 `beads-side` 素材。
- [用户决定] 珠串可视外缘离屏幕边至少 28px，触摸区宽度至少 56px，与人物保持至少 20px；箭头不压珠子，当前珠提示完整显示。
- [假设] 镜头保持侧后方，珠串作为相机前景层固定在屏幕右侧；世界坐标中的人物随镜头安全区微调，但不越过礼拜中轴。
- [用户决定] 结束：人物仍面向佛位；继续下一圈时不重置人物位置，离开时回到念珠位旁的等候点。

## 7. 3D 中的主尊规则

- [用户决定] 人物的导航网格到佛台前终止，不能走到佛位后面、侧后方或佛台上。
- [用户决定] 相机不得从主尊背后、脚下或低角度仰拍特写，也不得做 360°环绕。
- [用户决定] 人物、相机和交互射线都不能穿过供桌、香炉、油灯或佛台。
- [用户决定] 主尊不可点击；活动入口绑定香炉、蒲团、木鱼、念珠位和静坐位。
- [用户决定] 在造像规范另行确认前，只使用无面部、无持物的暖灰或淡金半透明剪影，坐在明确佛座上。
- [用户决定] 标题、计时、提示、按钮和加载状态都不得覆盖主尊身体、背光、供桌或香炉。
- [假设] 主尊保护区由屏幕投影包围盒加 16px 安全边距生成，横竖屏与镜头变化时每帧或每次相机稳定后重算。

## 8. “游戏式”边界

- [用户决定] 不做积分、等级、任务、连续签到、断签、排行榜或抽奖。
- [用户决定] 活动完成只显示计数、时长与温和结束语，不产生可比较的分数或虚拟身份等级。
- [用户决定] 不出现本地模拟访客、预录访客或虚增在线人数；真实多人未接入前，场景里只有用户本人。
- [用户决定] 真实多人以后接入时，只显示确实在线的匿名访客；人数少时保持安静，不补齐画面。
- [假设] 探索地图只用于空间导航，不设置收集物、每日任务或解锁进度。

## 9. 老人友好

- [用户决定] 首次进入最多三步：①点地面走；②靠近物件会出现按钮；③可随时点“不走路直接拜”；三步都可跳过且只展示一次。
- [用户决定] 主要按钮触控区至少 44×44px，底部活动文字至少 14px，场景标题至少 18px，返回按钮文字至少 16px，按钮间距至少 8px。
- [假设] 关键动作按钮在拇指易达的底部区域；“回到寺门”“不走路直接拜”不放在仅靠长按或手势才能发现的位置。
- [用户决定] 提供关闭镜头动画和减少动效；系统已开启减少动效时默认使用静态切换。
- [用户决定] 单手可以完成走路、进入活动、开始、暂停和返回；双指缩放不是完成流程的前提。
- [假设] 连续两次碰壁或 8 秒没有移动时显示一次“直接到佛前”提示，用户关闭后本次会话不再出现。

## 10. 手机硬指标与降级

- [已验证事实] 本地副本实测首屏约 4.8MB（Claude，2026-11-11，Playwright 393×659，无报错）。
- [假设] staging 实际值待部署核实后回填。
- [用户决定] 小镇首屏上限为 ≤6MB。
- [已验证事实] `CCGS-信息同步-20261107.md` §7 记录的 ≤10MB 是旧估，现已由“小镇首屏 ≤6MB”取代。
- [已验证事实] P0 代码自托管 three.js、使用纸片人物、限制设备像素比，并以固定相机跟随；证据为 `town-3d/scene.js`、`character.js` 与 `app.js:193–194`。
- [假设] 殿内首次进入新增必需资源预算不超过 3.5MB 压缩传输，其中场景和贴图 ≤2.0MB、人物当前身份帧 ≤0.8MB、几何与脚本 ≤0.5MB、余量 ≥0.2MB；小镇与殿内同一会话首个可操作路径累计 ≤8MB。
- [假设] 中低端安卓低档关闭实时阴影、粒子和后处理，将设备像素比限制到 1.0，远景改为单张平面，活动动作和碰撞仍完整保留。
- [假设] 若连续 5 秒 FPS 中位数低于 24，或 WebGL 初始化失败，则提示切换 2D；不在活动进行中自动切走。
- [假设] Telegram iOS/Android WebView 可能限制内存、后台恢复、声音解锁与手势边缘区域；必须分别测试首次进入、切后台 30 秒恢复、来回进殿 10 次和弱网重试。
- [用户决定] 2D 回退始终可见，且不把降级描述成失败或低配惩罚。

## 11. 分期、对接与过渡

### 11.1 第 1 期：云寺殿内 + 上香样板

- [用户决定] 第 1 期样板只做一位代表访客；范围只含云寺殿内和上香一个活动，部署到 staging 给用户真机试，现有线上 2D 不替换。
- [用户决定] 第 1 期样板约 23–27 张运行图 = 复用 15 张人物帧（7 张 P0 行走/合掌帧 + 8 张现有上香帧）+ 新增 8–12 张殿内贴图。
- [假设] 代码范围：殿内场景、导航网格与碰撞、进殿/回门、受限镜头、上香交互点、现有 L2 状态机适配、2D 回退、性能记录与截图测试。
- [假设] 对接方式：`town-3d` 负责从小镇门口进入殿内；主程序提供上香规则、计时、声音、统计与分享数据；不复制第二套业务计数逻辑。
- [假设] 工作量：一位访客技术样板约 11–17 人日，单人串行约 2–3 周。

### 11.2 第 2 期：云寺其余四项活动

- [用户决定] 在第 1 期通过后加入礼拜、木鱼、静坐、念珠，规则完全沿用第 5 章。
- [假设] 美术范围：复用礼拜 18 张、木鱼 18 张、念珠 18 张；新增约 6 张侧后静坐图及必要的 0–12 张过渡帧；共享蒲团、矮桌、木鱼和珠串道具约 4–8 张贴图。
- [假设] 代码范围：四个交互点、动作状态适配、活动专用镜头、念珠前景触控层、静坐简化 UI、统一完成/退出与分享构图。
- [假设] 对接方式：五活动继续调用主程序同一统计、声音、分享与本地偏好接口；`town-3d` 只负责空间、镜头和可视动作。
- [假设] 工作量：约 15–25 人日，真机交互与遮挡回归是主要不确定项。

### 11.3 第 2 期之后：六位访客覆盖扩展

- [用户决定] 六位访客覆盖列为第 2 期完成后的扩展项；第 1 期不铺开六位访客，待一位代表访客通过真机验收后再启动。
- [假设] 六位完整覆盖时，运行集约 102 张人物帧（54 张通用移动/站立 + 48 张上香），其中约 66 张可复用、约 36 张需补；加上 8–12 张殿内共享贴图后约 110–114 张运行图片，新增约 44–48 张。
- [假设] 从一位扩到六位约增加 5–8 人日，主要用于补帧、对位、身份一致性审图和真机回归。

### 11.4 第 3 期：其余六寺

- [用户决定] 其余六寺在云寺模板通过后扩展；寺名和称号未定处继续使用内部占位，不在用户界面自行定名。
- [假设] 每寺需独立殿内色彩、建筑结构、主尊剪影、供桌/香炉/灯具与碰撞配置；人物动作和五活动状态机尽量共用。
- [假设] 代码范围：寺庙配置表、场景按寺分包、坐标/碰撞覆盖、节日视觉入口与回退；不复制活动业务代码。
- [假设] 工作量：每寺约 8–15 人日，六寺约 48–90 人日，不含主尊规范反复审核的等待时间。

### 11.5 过渡与替换条件

- [用户决定] 过渡期线上默认使用现有 2D 殿内，3D 只在独立入口或 staging 开放。
- [假设] 3D 替换默认入口前必须同时满足：文化朝向逐项通过；目标设备中位 FPS ≥30；首次可操作路径 ≤8MB；五活动全流程无阻断；Telegram iOS/Android 可恢复；2D 回退可用。
- [假设] 发布采用功能开关 `3D_HALL_ENABLED` 与寺级白名单；回退只关闭开关，不删除 2D 素材、活动数据或用户记录。
- [用户决定] 3D 活动与 2D 活动共用同一完成口径，切换模式不能重复奖励、重置计数或改变用户隐私范围。

## 12. 验收标准

### 12.1 对第 1 章：取代关系

- [假设] 打开三份旧文档时，首屏能看到指向本文件的取代提示；原正文除新增提示外保持不变。
- [假设] 文档检索“不做自由漫游”“三固定视角”“3D 已暂停”“2D 为主力”时，本文件均给出明确的新结论而非并列冲突。

### 12.2 对第 2 章：行走

- [假设] 393×659 真机录屏中，轻点地面可到达目标，按住左右拖动可连续行走，松手立即停止继续转向。

### 12.3 对第 3 章：镜头

- [假设] 小镇行走、进殿、上香、礼拜各截一张图，人物全身和必要佛位都在画面内，镜头没有穿墙或从禁区观察。
- [假设] 开启减少动效后，所有镜头飞行消失，仅保留短淡化；连续切换 10 次不出现眩晕式旋转或画面跳跃。

### 12.4 对第 4 章：布局

- [假设] 俯视调试图能同时显示佛台、供桌、香炉、蒲团、木鱼矮桌、念珠位、静坐位和各碰撞框，且没有不可解释的重叠。
- [假设] 五活动各截一张 393×659 图，活动道具不遮佛位，人物脚/膝与目标物接触自然，上香画面不显示蒲团。

### 12.5 对第 5 章：五活动

- [假设] 每项活动用一段完整录屏验证“走到哪、如何开始、动作顺序、镜头、结束位置”五项都与 §5 对应。
- [假设] 六位访客各跑一次五活动，任何画面都不存在背对佛位、手槌分离、珠串隔在人佛之间、按钮遮住关键对象或错误结束位置。

### 12.6 对第 6 章：人物素材

- [假设] 每位访客的背面、斜侧、侧面动作总表能一眼辨认身份，头身比、衣服、发型和肤色在各朝向一致。
- [假设] 帧动画逐帧差异检查中，非动作区域无抖动；同一锚点切换站立、活动和结束姿势时脚底位移 ≤3px。

### 12.7 对第 7 章：主尊

- [假设] 自动相机巡检覆盖可达边界和所有活动机位，截图中没有主尊背面、脚下视角、低角度仰拍或 UI 覆盖。
- [假设] 点击主尊身体 20 次不触发活动；人物与相机尝试穿过佛台、供桌和主尊保护区均被阻止。

### 12.8 对第 8 章：边界

- [假设] 全部界面、完成页和分享卡截图中，不出现积分、等级、任务、签到、榜单或抽奖入口。
- [假设] 断网和无其他用户在线时，场景里始终只有当前访客，在线数字不会凭空增加。

### 12.9 对第 9 章：老人友好

- [假设] 首次引导最多三屏且可跳过；重新进入不重复强制显示，设置里可主动重看。
- [假设] 在 375×548、393×659、430×932 三个视口测量，主要触控区 ≥44px、字号和间距达到 §9，单手可完成上香与返回。

### 12.10 对第 10 章：手机指标

- [假设] iPhone SE 同级、iPhone 15、中低端安卓、Telegram iOS/Android 分别记录首次加载字节、可操作时间、FPS 中位数、峰值内存与休眠恢复结果。
- [假设] 强制 WebGL 失败与连续低帧两种场景都能进入 2D 回退；活动进行中不会被无提示切走。

### 12.11 对第 11 章：分期与回退

- [假设] 第 1 期发布包的变更清单只含云寺殿内、一位代表访客、上香、共用接口和测试，不夹带其余访客、其余寺或未验收活动。
- [假设] 关闭 3D 开关后，2D 五活动、计数、分享和家族功能仍可用，且用户数据不需要迁移或回滚。

### 12.12 对第 12 章：验收体系自身
