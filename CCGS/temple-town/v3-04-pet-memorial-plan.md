## 一人公司检查

- **AI 是主要生产力**：[用户决定]先做无照片、无信、无动态宠物的免费普通碑最小版；复用现有登录、邀请、删除/导出模式和小镇引擎，不增加新依赖。预计后端与接口约 4–6 人日、前端接入约 2–4 人日、机审词表与复核工具约 2–3 人日、联调与低端机性能验收约 2–3 人日 `[假设]`。需在 Codex E 的场景模块和 Codex A 的路由接入条件明确后细化。
- **情感细分、自带传播**：值得分享的一刻是主人立好碑，或看到“今天有几个人来过”；可分享碑链接/分享卡，首屏展示经机审的公开碑面，不登录即可看园、看公开内容 `[用户决定]`。不制造访客、留言或在线状态。首期指标 `[假设]`：建碑完成率 ≥60%、创建后 7 日回访 ≥15%、有至少一次真实访客行为的碑占比 ≥10%；不足时先访谈/检查流程，不靠虚构互动补数。
- **轻量化、单人可运营**：每日看自动告警与待复核队列；每周抽查误拦样本、滥用报告和备份恢复状态。先审后显、限速和自动归档降低人工量；人工申诉/退款仍需单列和值班边界。目标单人日常 ≤30 分钟 `[用户决定的目标，具体达到情况待验证]`。不引入线下服务。月服务成本目前缺少流量、存储、模型和供应商报价，列为上线预算输入，不能编造金额。突增时静态模型/贴图走 CDN、接口限流、队列排队；超过容量则暂停新建碑，已有纪念仍可读。

### 范围与接口冻结

- [用户决定]萌宠园是小镇九处中的独立一处；与七寺、先祖堂分开。访客不登录可进园、走动、看公开碑面、献花和点灯；建碑需身份。Telegram Mini App 自动识别用户并由服务端校验 `initData`；普通浏览器首块免费碑可用第一方随机编号，不采集设备指纹；次碑收费须绑定邮箱或 Telegram。普通碑免费规则受“首块免费、第二块起待收款接通才可建；一年无人来访移至纪念墙、不删除”约束。
- [用户决定]公开碑面仅宠物名字、种类图标、出生/离开年份、一句话，不显示主人身份。公开文案须先机器审核再显示。碑详情首期不含照片与信，只对主人和已邀请的人可见；陌生访客只献花/点灯，不留言；主人只看当天人数，不看到访客身份。
- [用户决定]独立墓地按收费设计，但收款与主体方案未提供：预留能力开关，未接通时照常展示为 `Sắp mở`，不可预订。此项不阻塞本期免费普通碑。
- 代码边界：只新增 `server/pet-*.mjs` 和 `pet_` 前缀数据库表；不得改 `server/index.mjs`、`server/family-*`、家族配置或已有接口。路由挂载若必须改现有文件，先回执提请 Codex A/Claude 安排，不在本派单内改。

### Codex B 后端文件与表

以下为拟定新增文件/契约 `[假设]`，实现前由本清单复核通过并确认由路由维护者接入：

- `server/pet-store.mjs`：SQLite 萌宠园专属存储；建表与查询封装，不触碰 `openFamilyStore`。
- `server/pet-api.mjs`：萌宠园 HTTP handler；只处理 `/api/pet-garden/*`，校验字段、身份、状态与速率，不改现有 family API。
- `server/pet-moderation.mjs`：确定性词表预检接口（`moderatePublicText({ name, epitaph, locale })`）；词表版本化并记录结果，不把用户原文写入分析事件。首期无外部模型调用，降低成本和数据外传；越南语变体、广告和冒名命中由人工复核迭代。
- `server/pet-telegram-auth.mjs`：若现有 `validateInitData` 可安全复用，应由新 handler 调用现有安全模块；不得复制一份弱化验证实现。此处需要路由 owner 核对允许的 import 边界。
- `pet_memorials`：`id`、`owner_ref`、`identity_kind`、`browser_claim_hash`（仅普通浏览器随机认领号的不可逆摘要）、`pet_name`、`species_code`、`born_year`、`died_year`、`epitaph`、`public_status`（pending/visible/rejected/hidden/wall）、`moderation_status`、`moderation_rule_version`、`moderation_reason_code`、`district_id`、`row_no`、`column_no`、`created_at`、`updated_at`、`last_qualifying_visit_at`、`wall_at`、`demo`。原文必须只留在业务表，限制访问；不复制到匿名分析库。
- `pet_members`：`memorial_id`、`principal_ref`、`role`（owner/invited）、`created_at`、`revoked_at`；唯一约束防重复邀请成员。复用家族邀请的安全思路，不复用家族白名单，也不把家族实体建模为宠物碑。
- `pet_invites`：随机 token 摘要、创建者、有效期、撤销时间、使用次数/上限、关联碑；明文 token 只在生成时返回。
- `pet_visits`：每日去重计数所需 `memorial_id`、不可逆的当日访客去重摘要、动作类别（open/flower/light）、时间；主人端只输出聚合人数，不提供可识别访客列表。保留期限和去重窗口 `[假设·需律师确认]`。
- `pet_offerings`：`memorial_id`、kind（flower/light）、访客去重摘要、日期和 `demo`；只允许无文字动作，支持按日计数和限速。是否把“点开碑面”计作周年活跃，暂建议只将主动献花/点灯计作访客，主人自己的访问不计、路过不计 `[假设]`，避免无意浏览维持碑位。
- `pet_rates`：按主体摘要、IP 短期摘要和动作键限速；IP 技术日志继续沿现有最多保留七天、只留前两段的口径，不进入产品身份表。
- `pet_analytics_events`（仅在 `analytics-choice` 同意后写）：匿名访客编号、浏览器/系统类型、设备类别、屏幕尺寸档、语言、来源、页面/动作、时间。与认碑身份表分离；不写碑文、不写 Telegram ID/邮箱/认碑随机编号。匿名编号与身份映射不得在后台报表可见。
- 后续才新增：照片对象元数据/存储键、信件内容与权限字段、付费订单/权益期限和状态；需 P15 与收款主体方案，不进入第 1 期 schema。

### Codex B HTTP 契约

所有返回 JSON；访客端仅返回公开字段。所有写操作服务端重新鉴权并限速；错误不回显被拦原文。

| 方法与路径 | 身份 | 用途 / 输入 | 返回 |
|---|---|---|---|
| `GET /api/pet-garden/memorials?district=&cursor=` | 匿名 | 分页读取当前片区公开碑摘要；仅 `visible` | `items[{id,petName,speciesCode,bornYear,diedYear,epitaph,rowNo,columnNo}]`、`nextCursor` |
| `GET /api/pet-garden/memorials/:id` | 匿名 | 单碑公开面；详情另经成员校验 | 公开字段、真实聚合当日花/灯人数 |
| `GET /api/pet-garden/memorials/:id/private` | owner/invited | 取首期私密日期等内容；验证 `pet_members` | 主人/受邀可读字段，不含照片/信 |
| `POST /api/pet-garden/memorials` | Telegram 已验 `initData`；或浏览器随机 claim | `petName,speciesCode,bornYear,diedYear,epitaph,visibility`；先机审再公开；普通浏览器仅首碑免费 | `id,publicStatus,claimToken?`（浏览器 token 仅一次展示） |
| `POST /api/pet-garden/memorials/:id/claim` | 已绑定 email/Telegram | 将浏览器随机号下的碑并入账号；只允许摘要匹配且碑未被绑定 | `claimed:true` 或无信息泄露的冲突码 |
| `POST /api/pet-garden/memorials/:id/invites` | owner | `maxUses,expiresAt`；创建邀请 | 一次性邀请 URL/token、有效期 |
| `POST /api/pet-garden/invites/:token/accept` | Telegram 或绑定账号 | 接受邀请并建立只读成员关系 | `memorialId,role` |
| `DELETE /api/pet-garden/memorials/:id/invites/:inviteId` | owner | 撤销邀请 | `revoked:true` |
| `POST /api/pet-garden/memorials/:id/offerings` | 匿名访客 | `kind=flower|light`；按匿名主体和碑限速 | 更新后的真实当日汇总数；幂等重试不重复计 |
| `GET /api/pet-garden/mine` | Telegram 或绑定账号；浏览器 claim 仅本机 | 我的碑与 `district/row/column` 导航定位 | 列表、状态、坐标，不返回其他成员身份 |
| `GET /api/pet-garden/mine/:id/visits?day=` | owner | 只读取聚合“今天有 N 人来过” | `date,uniqueVisitors,flowers,lights` |
| `DELETE /api/pet-garden/memorials/:id` | owner | 删除碑及成员/邀请/动作明细；依法须保留的最小交易记录另行隔离 `[假设·需律师确认]` | `deleted:true` |
| `POST /api/pet-garden/reports` | 匿名 | `memorialId,reasonCode` 举报公开碑；每主体限速 | `accepted:true,reportId` |
| `GET /api/pet-garden/analytics` | 管理员现有只读授权 | 汇总匿名事件，无身份、碑文、个体路径 | 聚合看板数据；须 Codex A 接入现有后台，后台仍只读 |

**机审与申诉**：公开名字和一句话在任何访客可见前执行越南语/英语词表规范化匹配；命中即 `rejected` 或 `pending_review`，拒绝原因仅给类别与修改提示，不展示命中规则以免帮助绕过。采用先审后显，禁止未经审查的先显后审。词表来源应从顾问提供的越南语辱骂、广告及冒名样本开始；没有经顾问核定的词表之前不开放公开建碑。首版人工复核由后台审核队列执行，申诉进入同一队列，记录审核人、时间、理由与规则版本；误判前保持不可见。验证码/邮件发送限速复用现有模式，但访客献花点灯不要求登录。后台复核是人工工作量，首期每天抽查和申诉处理目标合计 ≤30 分钟 `[假设]`，超出即暂停新碑或缩小开放量。

**身份冲突**：浏览器 claim token 用高熵随机数、第一方存储，不含设备特征，服务端只保存 hash。绑定时用事务完成认领；若同一碑已有另一身份认领，绝不自动覆盖，返回通用冲突说明，原 owner 继续有效，申诉走人工审核并验证可用凭证。找回凭证丢失无法仅凭浏览器指纹恢复。

## 产品定位、地点与访问体验

- [用户决定]中文名称“萌宠园”；越南语名待用户/顾问定。它服务于想保存宠物记忆、需要一个安静纪念地点、或愿意在公共园区做无文字善意动作的人。它不承担治疗、宗教仪式或保证情绪改善的作用。
- [用户决定]它是小镇九处中独立的一处“宠物堂”，与先祖堂及七座寺分别设置；不可放进祖先牌位，也不放佛殿正中。具体方位及相邻关系归 P13 决定，本稿不定坐标。
- [用户决定]开放式集中墓园：普通碑成排成列，另有一座墓加一小片园子的独立墓地。任何访客可沿路步行、点地面行走或按住拖动视角；不可穿过碑体或被镜头推入碑面。入口、片区走道和独立园子入口保持连通。提供“我的碑”直达与片区/行/列编号查询，减少必须漫游才能找到碑的负担。
- [假设]第一片区 8×8 槽位，走道净宽目标 2m；槽位无人使用时维持草地，不预置填充碑。新增片区按使用率达到 70% 才开下一片区，并优先自动分配空位。上述尺寸、阈值需 Codex E 场景走测和 P13 坐标确认。

## 虚拟宠物：选项与建议

- **做可交互会动宠物**：触摸、跟随、动画可能提供陪伴感，但可能使部分人更难接受失去，也增加动画、碰撞、状态同步和性能维护，首期不建议。
- **不做**：情绪和维护成本最低，但少了“陪它一会儿”的视觉锚点。
- **只做静态画像**：将来在主人或受邀者可见的碑前展示单张温和插画/用户自选图片，不伪装宠物仍在场；交互仅是打开回忆，不响应抚摸、不主动呼唤 `[假设]`。
- **建议**：第 1 期不做；第 2 期验证真实照片/信使用需求后，再由用户决定是否加入静态画像。提供随时关闭和不显示的选项，避免产品暗示宠物仍“在线”。

## 隐私、账号和条款改动

- [用户决定]“逛园不登录、什么都不记”指不记录访问者**身份**；用户同意可选统计后可记去身份化的分析事件。游客不授权统计时，不向分析库写事件，仅保留现有口径的技术日志。沿用 `analytics-choice` 的 `Đồng ý` 开关，不默认打开。
- 认碑身份：Telegram 服务端验证后的用户标识、邮箱/账号绑定；普通浏览器首碑随机 claim 编号。claim 编号仅一方本地保存且随机生成，不由屏幕、字体、Canvas、设备型号等特征推导；服务器仅存摘要。账号关联与匿名分析 visitor ID 分表、分权限，后台报表不得反查身份。
- 同意后统计字段限于随机匿名访客编号、浏览器/系统大类、手机/平板/电脑、屏幕尺寸档、语言、来源渠道、页面和动作。不得存碑文进分析库，不存完整 IP；遵守现有技术日志只保留 IP 前两段、最长七天。分析保留期限须由律师和运维共同定，默认建议原始事件 90 天后汇总删除 `[假设·需律师确认]`。
- 上线前修改 `quyen-rieng-tu.html`：明确随机 claim 编号用途/清除方式、Telegram 身份处理、分析字段及同意/撤回路径、事件保存期限、删除和导出、受邀成员可见范围、审核和举报处理、第三方/跨境处理方及联系渠道。修订服务条款：公开碑面的永久/转纪念墙规则、主人上传内容授权、邀请与撤销、内容审核/隐藏申诉、删除例外、账号找回失败和有期限服务的处理。加入删除纪念与合法留存之间的流程说明。
- [假设·需律师确认]越南《个人数据保护法》91/2025/QH15 自 2026-01-01 生效；实施细则也在 2026 年变动。必须让熟悉越南当前个人数据规则的律师核对处理者责任、未成年人、跨境传输、同意撤回、删除时限、匿名化是否仍属个人数据、日志、cookie、analytics SDK 和数据处理者合同。官方法律入口：[政府法令库 Law 91/2025/QH15](https://vanban.chinhphu.vn/?classid=1&docid=214590&pageid=27160&typegroup=)。旧 Decree 13 的英文说明不应当作 2026 年现行完整法律依据。
- 收费园区上线另请律师核对消费者保护、线上合同/撤销、税与发票、退款、经营主体和到期权益；不得在法律评审前收款。
- 现有管理后台当前只读、一个邮箱白名单（项目背景记录）；萌宠园看板新增一页只给匿名汇总，无姓名、Telegram ID、邮箱、原碑文、单访客轨迹。若后台需审核操作，则应作为后续被授权范围单独定义权限和审计日志。

## 商业化选项、墓园整理与不做清单

- [用户决定]普通第一碑免费；第二块普通碑起收费，但收款接通前显示 `Sắp mở` 且不能创建。独立墓地为收费的大占地小园子，同样无支付/主体方案时只做场景和开关，不接订单，不允许预订。不得收费才能得到基本纪念。
- 可研究的收费模型只列选项、不定价：第二碑一次性费用；独立墓地一次性购买或按期维护。一次性可能带来长期存储和删除成本无资金覆盖；按期可能被误解为到期删除，必须提供提醒、宽限期、降级到普通碑/纪念墙而不删除内容，并支持退款及依法开票。未接支付不可产生待付款订单。
- [用户决定]所有碑一年没有“合格来访”后转入纪念墙而非删除；建议只有访客主动献花或点灯算有效来访；主人自己的查看、路过、机器人/预取请求不算。移动前建议 30 天、7 天各提醒一次，但家族提醒定时器当前关闭，萌宠园不得擅自打开或共用其设置；应将独立消息通道、模板、退出方式及用户授权列为后续设计决定。浏览器随机认领且未绑定账号者无法跨设备通知，展示状态提示即可。
- 纪念墙永久保留公开碑面需与隐私删除要求协调；主人能请求删除，合规保留原因与期限由律师确认。主人“请回”时若原位已占，则分配当前片区空位并更新地图坐标，保留原碑 ID 和动作历史的最小摘要 `[假设]`。
- 独立墓地场景可包括低矮围栏、花圃、单块碑和非写实小摆件；不得默认十字架、香炉、祖先牌位或佛像。位置大于普通碑、使用空间上限和访客路径待 Codex E/P13 定。收费期结束不得删碑，建议提醒后宽限 90 天并降级为普通碑；但独立园子的额外装饰如何收起属待用户决定。
- [用户决定]不做积分、等级、签到、排行榜、抽奖、假人、假在线人数、假碑、功效售卖；不出现与死后去向/宗教效力有关的保证措辞；不做“吹香”；佛像只可无面部无持物剪影。本期不做实物、线下场地、物流或仓储。
